# 관리자 운영 도구

## 접근과 권한

`/admin`은 Google 로그인 후 서버에서 확인한 `app_metadata.role = admin` 계정만 사용할 수 있습니다. 일반 사용자가 수정할 수 있는 `user_metadata`는 권한 판정에 사용하지 않습니다. 현재 Google 공급자 설정과 운영자 계정 지정이 남아 있어 실제 운영자 로그인으로 화면 저장을 검증하는 단계는 아직 완료되지 않았습니다.

운영자 계정은 가입 후 해당 계정 UUID를 확인해 Supabase 관리 API 또는 SQL Editor에서 `auth.users.raw_app_meta_data`의 기존 값을 보존하면서 `role: admin`을 추가합니다. 임의의 이메일이나 첫 가입자를 자동으로 관리자로 만들지 않습니다. 역할 변경 후 다시 로그인하여 토큰을 갱신합니다. 권한 회수 시 기존 토큰 만료/세션 회수도 고려해야 합니다.

## 화면

- `/admin`: 전체 콘텐츠 수, 공개 설정 수, 조회 가능한 평가·한줄평 수
- `/admin/content`: 게임·편·장·캐릭터·등장 관계 검색 및 편집. 제목, 설명, 공개 여부, 순서, 공개일, 이미지 경로 수정
- `/admin/import`: Excel 검사, 오류·확인 사항, 변경 전후 비교, 일괄 적용
- `/admin/settings`: 평가/한줄평·좋아요 등록 허용, 홈 목록 수
- `/admin/history`: 관리 도구로 적용한 최근 100건의 이전/이후 내용과 작업자
- `/games/[gameSlug]/stats`: 이용자용 게임/장 평가 통계

기존 ID·주소·부모 연결을 편집 화면에서 바꾸지 않습니다. 저장할 때 읽었던 `updated_at`과 현재 값을 비교하고 충돌하면 다시 불러와 검토하도록 차단합니다. 일괄 적용은 하나의 DB 트랜잭션으로 수행하고, 한 건이라도 실패하면 데이터와 변경 기록을 모두 롤백합니다. 누락 행과 기존 자료를 자동 삭제하지 않습니다.

## Excel 형식과 보존 규칙

매핑은 `config/import/blue-archive.json` 한 곳에서 관리합니다. 웹 파서는 기존 Python 파이프라인과 같은 시트·헤더 매핑을 사용하며 원본은 수정하지 않습니다. 수식은 계산하지 않고 Excel이 저장한 결과를 읽습니다. ID/이름 조회 결과가 서로 다르면 재계산 후 저장해야 합니다.

| 시트 | 헤더 행 | 주요 열 |
|---|---|---|
| CHARACTERS | 3 | 넘버, character_id, name, 비고, 사진 |
| STORIES | 2 | Story_ID, Parent_ID, Type, 제목, KR, JP, 공개상태, 줄거리 |
| Appearances | 2 | story_id, No, character_id, name, display_order, note |

기존 항목은 공개 상태, 주소, 이미지, 순서를 보존합니다. 이름·제목·줄거리·공개일의 변경은 비교표에 표시합니다. 새 게임과 캐릭터는 비공개로 추가합니다. 새 편·장은 오늘까지의 한국 공개일이 있을 때 공개 상태로 준비하며, 부모 게임이 비공개면 실제 사이트에는 노출되지 않습니다. 기존 예약 행 제외와 최종편 ID 보정은 Blue Archive 매핑에만 적용합니다.

다른 게임도 동일한 시트 양식이면 게임 정보 영역에 고유 게임 ID·주소·이름을 입력해 추가할 수 있습니다. 다른 시트 양식은 매핑/파서 추가가 필요합니다. 새 이미지 파일 업로드는 이번 웹 가져오기 범위에 포함되지 않으며, 이미지가 없는 새 항목은 placeholder를 사용합니다. Storage에 이미 등록된 파생본의 경로는 콘텐츠 편집에서 연결할 수 있습니다.

파일 제한: XLSX 2MB, 압축 해제 합계 20MB, ZIP 구성 요소 500개, 파일 내 데이터 10,000행, 한 번에 변경 3,000건. 변경이 많으면 파일을 나누어 검토합니다. 서버가 적용을 완료했는지 알 수 없는 연결 오류가 발생하면 같은 요청을 무작정 재전송하지 말고 파일을 다시 검사해 현재 상태와 비교합니다.

## 검증 기록

- 실제 제공 Excel: 214명, 12개 편, 29개 장, 703개 등장 관계를 기존 파이프라인과 동일하게 판독
- Node importer 테스트 4개 통과: 매핑/공개 정책, 동일 파일 재반입 변경 0건, 수식 결과 불일치·누락 열 차단, 입력값 검사
- `tests/admin-rls.sql` 통과: 일반 사용자 및 user_metadata 권한 위조 차단, 관리자 비공개 조회/신규/수정, 충돌 거절, 실패한 일괄 적용 전체 롤백, 변경 기록, 익명 비공개 차단
- 기존 `tests/rls.sql` 회귀 검증 통과. 모든 SQL 테스트는 rollback하여 실제 데이터를 바꾸지 않음
- 관리자 스키마 적용 후 Supabase 보안 진단 경고 0건

원본 데이터가 로컬에 있을 때 `node --test tests/import.test.mjs`로 Excel 통합 테스트를 실행할 수 있습니다. 관리자 로그인 후 브라우저에서 파일 검사→변경 검토→저장 흐름의 최종 검증이 추가로 필요합니다.
