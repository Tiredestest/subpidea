# 실제 자료 분석 및 전처리 결과

분석 기준: 2026-09-20. 원본 Excel과 이미지는 수정하지 않았다.

## 확인한 자료

| 자료 | 위치·규모 |
|---|---|
| Excel | data/raw/excel/블루아카이브.xlsx |
| 캐릭터 이미지 | data/raw/images/characters/BA_CH_images — 214개 |
| 스토리 이미지 | data/raw/images/stories/BA_ST_images — 41개 |
| 구조 레퍼런스 | data/raw/ui-references/전반적인 구조.png |
| 벤치마크 | 저장된 HTML의 원본 주소 https://pedia.watcha.com/ko |

폴더 이름은 정해진 약칭과 달라도 된다. importer 설정 파일에 실제 경로를 지정하므로 현재 폴더 구조를 유지할 수 있다.

## Excel 구조

| 시트 | 헤더 행 | 주요 컬럼 | 원본 행 수 |
|---|---:|---|---:|
| CHARACTERS | 3 | 넘버, character_id, name, 비고, 사진 | 215 |
| STORIES | 2 | Story_ID, Parent_ID, Type, 제목, KR, JP, 공개상태, 줄거리 | 41 |
| Appearances | 2 | story_id, No, character_id, name, display_order, note | 707 |

STORIES의 VOL 12개를 편, Chapter 29개를 장으로 분리한다. 별도 games 시트는 없으므로 게임 ID BA, slug blue-archive, 제목 블루 아카이브는 게임별 import 설정에서 제공한다. UI 컴포넌트에 넣지 않는다.

CHARACTERS의 넘버와 Appearances의 No는 Excel 작업용이다. 실제 연결은 character_id로 수행한다. Appearances의 character_id/name은 VLOOKUP 수식이므로 캐시값을 읽되 현재 캐릭터 마스터의 번호·ID·이름과 대조한다. 값이 없거나 일치하지 않으면 임의 보정하지 않고 변환 실패 처리한다.

## 발견한 차이와 처리

| 항목 | 실제 상태 | 이번 처리 |
|---|---|---|
| 최종편 ID | Appearances는 BA_CHF-1~4, STORIES와 이미지는 BA_CH_F-1~4 | 설정 파일의 명시적 별칭 4개로 278행 정규화. 원본 유지 |
| 미사용 캐릭터 | CHARACTERS 191행 BA_C_187의 이름·이미지가 없고 등장 참조도 없음 | 입력 대상에서 격리. 정체나 이름을 추측하지 않음 |
| 비어 있는 등장 행 | Appearances 250/252/254/256행에 장 ID만 존재 | 격리하여 입력 제외. 캐릭터를 임의 지정하지 않음 |
| 장 순서 | BA_CH3-4가 BA_CH3-3보다 위에 있음 | 장 ID 끝 번호로 편 안 순서 지정 |
| 표시 순서 | display_order 전체 공란 | 같은 장 안에서 원본 등장 행 순서 유지 |
| 공개 상태 | 스토리 41개 모두 공란 | 사용자가 선택한 한국 공개일 기준 반영 |
| 출시일 | KR/JP 두 컬럼, 7개 스토리는 KR 없음 | 두 날짜를 분리 보존. KR 없으면 초기 비공개 |
| 등장 관계 누락 | BA_CH7-1, BA_CH7-2, BA_CH8-1 | 빈 관계로 보존하고 경고. 현재 모두 비공개 |
| 인물 정보 | 학교·동아리·소개 컬럼 없음 | 화면 예시에 있는 학교·소속을 임의 생성하지 않음 |
| 게임 대표 이미지 | 별도 파일 없음 | 첫 화면 구현 시 공통 placeholder 또는 운영자가 지정한 이미지 사용 |

변환 후 입력 준비 데이터: 캐릭터 214, 편 12, 장 29, 등장 관계 703. 유효 데이터의 이미지 ID 대응은 모두 확인됐다. 전체 원본 255개 이미지 중 매핑되지 않은 이미지나 깨진 이미지가 발견되지 않았다.

## 공개 정책

사용자 확정: 한국 공개일이 있는 스토리만 초기 공개한다. 아직 오지 않은 한국 공개일도 공개 대상에서 제외한다. 기준일 현재 공개 대상은 편 10개, 장 24개다. KR/JP는 입력된 Excel 날짜를 사용했으며 외부 출시 정보와 대조한 결과는 아니다.

초기 캐릭터 공개는 공개 장에 등장 관계가 확인된 173명으로 제한하는 보수적 구현안을 적용했다. 나머지 41명도 입력 준비 데이터에 보관한다. 등장 관계가 없다는 이유만으로 미출시 인물이라고 단정한 것은 아니다. 캐릭터 전체 공개를 원하면 별도 정책으로 변경 가능하다.

초기 공개 정책은 첫 import의 기본값이다. 이후 일상적인 import가 Studio에서 수정한 공개 상태를 덮어쓰면 안 된다. 실제 DB importer를 연결할 때 최초 입력과 재입력의 갱신 필드를 구분해야 한다.

## 이미지 최적화

전체 스토리 중 28개가 1600×1124이며 주요 원본의 비율은 약 1.42:1이다. 이 비율에 맞춰 다음 웹용 파생본을 만들었다.

| 용도 | 표준 출력 | 전체 용량 |
|---|---|---:|
| 스토리 원본 41개 | JPG/PNG/WebP 혼합 | 10.39 MB |
| 스토리 카드 | 640×450 WebP | 1.17 MB |
| 스토리 상세 | 1280×900 WebP | 2.88 MB |
| 캐릭터 원본 214개 | 다양한 크기 WebP | 10.26 MB |
| 캐릭터 선택 아바타 | 128×128 WebP | 0.66 MB |
| 캐릭터 상세 | 512×512 WebP | 3.69 MB |

MB는 1,000,000 bytes 기준. 스토리 카드 묶음은 원본 대비 약 88.7%, 상세 묶음은 약 72.3% 감소했다. 한 화면에서 카드와 상세를 모두 불러오는 방식이 아니라 표시 용도에 맞게 선택한다.

원본을 늘이거나 자르지 않는다. 큰 이미지는 축소하고 작은 이미지는 원래 해상도 이상으로 확대하지 않으며, 나머지 영역을 밝은 회색 여백으로 채운다. 600×375 최종편 대표 이미지처럼 작은 원본은 큰 출력 캔버스에서도 실제 디테일이 증가하지 않는다. 더 선명한 확대가 필요하면 고해상도 원본 교체가 필요하다.

출력 위치: data/processed/blue-archive/stories 및 characters. 총 510개 파생 이미지를 만들었고 manifest.json에 원본 해시·출력 경로·크기·용량을 기록했다. 변환 중 모든 파일의 출력 크기/형식을 검사했으며 가로형·대형·저해상도 사례를 육안 확인했다.

## UI 반영 방향

구조는 제공한 전반적인 구조.png를 기준으로 한다. 홈/검색에서 장으로 바로 이동, 편별 장 탐색, 장 왼쪽 정보와 오른쪽 캐릭터 패널, 동일 화면에서 캐릭터 전환을 우선한다.

벤치마크 [왓챠피디아](https://pedia.watcha.com/ko)에서는 검색 진입과 콘텐츠·평가 정보의 배치 방식을 참고한다. 첫 디자인 방향은 제공된 구조 이미지의 밝은 바탕과 남색/파랑 강조색, 이미지와 제목 중심의 카드다. 저장 HTML은 dark 테마였으므로 다크 모드 선호가 있다면 이후 조정할 수 있다.

구조 이미지 안의 4.7점·평가자 수·코멘트는 예시로 취급한다. 실제 평가가 없으면 ‘아직 평가 없음’을 표시하며, 임의 평점을 데이터로 입력하지 않는다. 레퍼런스의 다른 게임들도 데이터가 전달된 게임으로 간주하지 않는다.
