# 관리자 이미지 일괄 업로드

고정 주소: https://subpidea-preview-tiredestests-projects.vercel.app/admin/images

## 사용 순서

1. 새 콘텐츠는 Excel 가져오기에서 먼저 등록한다.
2. 관리자 → **이미지 관리**에서 게임과 대상 종류(스토리 / 캐릭터)를 선택한다.
3. 여러 파일을 선택하거나 끌어 놓고 **파일 검사**를 누른다. 검사만으로 이미지가 저장되거나 콘텐츠가 변경되지는 않는다.
4. 원본 미리보기, 연결 대상, 생성 크기, 신규/기존 이미지 교체 표시를 확인한다.
5. 확인란을 선택하고 **정상 N개 적용**을 누른다. 오류·중복 파일은 제외되며 완료 후 목록에 남는다.

| 대상 | 기본 파일명 | 따로 지정할 때 |
|---|---|---|
| 이벤트 | BA_EV001.png | BA_EV001-card.png / BA_EV001-detail.png |
| 메인 편 | BA_CH1.png | BA_CH1-card.png / BA_CH1-detail.png |
| 메인 장 | BA_CH1-1.png | BA_CH1-1-card.png / BA_CH1-1-detail.png |
| 캐릭터 | BA_C_001.png | BA_C_001-avatar.png / BA_C_001-portrait.png |

기본 파일은 두 용도를 함께 생성한다. ID는 Excel과 정확히 일치해야 하며 게임별로 조회한다. 다른 게임에도 같은 규칙을 사용한다. 이벤트는 같은 source ID의 편·평가 대상 양쪽을 함께 연결한다.

PNG/JPG/JPEG/WebP 정지 이미지, 파일당 3MB, 1회 최대 100개·총 100MB를 지원한다. 서버가 확인하는 이미지 픽셀 상한은 2천만이다. 너무 큰 원본은 별도 사본을 줄이거나 파일을 나누어 준비한다.

기본 이미지와 -card 이미지처럼 같은 대상·용도가 겹치면 둘 다 중복으로 표시한다. 하나를 제거하면 남은 파일을 적용할 수 있다. 대상이 없으면 Excel부터 적용한다. 오류를 수정한 파일은 다시 선택하고 검사한다.

## 처리와 보존

- 비율 유지, 확대·잘라내기 없이 중앙 배치·여백 보정, WebP 품질 82. 스토리 카드 640×450, 상세 1280×900, 캐릭터 썸네일 128×128, 상세 512×512.
- 원본은 로컬 파일을 변경하지 않으며 서버에는 변환본만 저장한다. 원본은 별도 보관한다.
- 각 파일을 순차 업로드한 후 이미지 연결을 하나의 관리자 트랜잭션으로 적용한다. 공개 여부·평가·한줄평은 변경하지 않는다.
- 기존 객체를 덮어쓰지 않고 내용 해시로 새 경로를 생성한다. 이전 객체와 DB 변경 기록은 보존한다. 기존 변경 기록의 경로는 콘텐츠 편집에서 복원할 수 있다.
- 검사 이후 대상이 바뀌면 업로드 또는 최종 저장 단계에서 충돌로 중단한다. 다시 검사해 변경 내용을 확인한다.
- 중도 실패 시 연결되지 않은 변환본이 private Storage에 남을 수 있다. 동일 이미지 재시도는 기존 객체를 재사용한다. 자동 삭제는 구현하지 않았다.
- Excel 재가져오기는 이미 설정된 스토리·캐릭터 이미지 경로를 보존한다. 게임 GAMES 시트의 명시적인 이미지 변경 동작은 유지한다.
- 게임 헤더는 같은 페이지 아래의 기존 헤더 업로드 기능을 사용한다.

## 권한과 검증

모든 파일 검사·업로드는 서버에서 관리자 세션과 Origin을 확인한다. Storage INSERT는 관리자 app_metadata 역할, 등록 게임, 지정된 폴더·해시 파일명에만 허용한다. UPDATE/DELETE 권한을 새로 부여하지 않았다. 공개 콘텐츠와 연결되기 전 변환본은 익명 조회할 수 없다. [Supabase Storage 접근 제어](https://supabase.com/docs/guides/storage/security/access-control)를 기준으로 구현했다.

- 자동 테스트 17개 통과: 파일명·종류·이벤트 쌍·중복·동시 수정 충돌·이미지 변환과 제한·Excel 이미지 보존, API 검사 무쓰기와 파일/대상 변경 거절, 기존 기능 회귀.
- 실제 Supabase SQL 권한 테스트 통과 후 rollback: 비관리자 거절, 관리자 INSERT, 미등록 게임/잘못된 폴더/기존 경로 거절, 변경 금지, 미연결 객체 비공개.
- 로컬 및 Vercel 프로덕션 빌드 통과. 배포 API의 비로그인 POST 응답 403 확인.
- 로그인된 브라우저의 파일 선택 → 최종 적용 실사용은 아직 미확인(브라우저 로그아웃 상태). 관리자 로그인 후 처음에는 파일 한 장으로 확인할 수 있다.
- 보안 진단 신규 경고 없음. 기존 [유출 비밀번호 보호 비활성화](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) 경고 1개 유지.
