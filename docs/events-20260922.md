# 블루 아카이브 이벤트 업데이트

## 사용 순서

1. 고정 미리보기의 `/admin/import`에서 `data/raw/excel/블루아카이브.xlsx`를 선택한다.
2. **파일 검사** 후 변경 사항과 경고를 확인한다. 검사만으로 콘텐츠가 저장되지는 않는다.
3. 변경 확인 체크 후 **일괄 적용**한다. 이벤트 이미지 연결도 함께 반영된다.
4. 게임 화면의 **메인(개수) / 이벤트(개수)**를 눌러 확인한다. 개수는 현재 공개된 콘텐츠 기준이다.

이번 작업에서는 기능과 이미지 업로드만 배포했다. Excel 콘텐츠를 실제 반영하는 일괄 적용은 사용자가 관리자 화면에서 진행한다. 따라서 적용 전에는 이벤트 개수가 0이다.

## 원본 검사 결과

- 이벤트 51개, 빈 이벤트 예약 행 2개(BA_EV052, BA_EV053) 제외.
- 2026-09-22 기준 한국 공개일이 지난 이벤트 48개는 신규 공개 대상. 일본 공개일만 있는 EV048~050은 비공개.
- 이벤트 이미지 48장과 새 캐릭터 이미지 3장: 원본 비율 유지·확대 금지·여백 보정으로 WebP 변환. 카드 640×450, 상세 1280×900, 캐릭터 128×128/512×512.
- 102개 변환 파일(약 7.6MB)을 기존 private Storage에 업로드. 업로드 임시 함수는 완료 직후 HTTP 410으로 닫음.
- Appearances 849행/850행은 847행/848행과 동일, 1205행은 1188행과 동일. 값까지 같은 중복은 경고 후 최초 행만 반영. 서로 다른 중복은 오류.
- 이벤트 외 변경: `정오의 아지랑이`/`드럼통 속에 있는 것` 한국 공개일 추가, `키누카와 카스미` → `키누가와 카스미`.
- 점검 당시 변경 계획 747건, 동일 965건, 오류 0건. 이후 관리자 수정에 따라 건수는 달라질 수 있음.

신규 캐릭터 3명과 기존 비공개 캐릭터는 자동 공개하지 않는다. 이벤트 출연진에 표시하려면 관리자 콘텐츠 화면에서 공개 여부를 확인한다. 기존 스토리 공개 여부도 유지하므로, 날짜가 새로 입력된 메인 장 2개의 공개는 별도로 설정한다.

## 구현

- `story_arcs.story_kind`: `main` / `event`, 기존 레코드는 main.
- Event 행은 이벤트 편과 동일 source ID의 평가 단위 chapter를 하나씩 생성. 출연진은 Event ID에 연결. 기존 별점·한줄평·RLS를 그대로 사용한다.
- 이벤트 카드는 상세·평가 화면으로 직접 연결. 장 이동 표시를 숨기고 이벤트 용어 사용.
- `?story=main` / `?story=event`로 필터 상태 유지. 알 수 없는 값은 main.
- 이번에 업로드한 이미지 경로는 `config/import/blue-archive-assets.json`에서 관리. 원본 Excel과 이미지는 Git에 포함하지 않음.
- 이후 새로운 이미지를 원본 폴더에 넣는 것만으로 서버에 전송되지는 않는다. 최적화·Storage 업로드·경로 매핑 갱신 후 Excel을 검사한다. Excel에 이미지를 포함하는 자동 업로드 기능은 이번 범위에 포함되지 않는다.
